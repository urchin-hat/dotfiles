# Security

## 基本原則

Gitリポジトリは将来公開される可能性があるものとして扱います。非公開リポジトリであっても、次の情報は平文で保存しません。

- パスワードとPIN
- APIキーとアクセストークン
- SSH、GPG、TLSなどの秘密鍵
- Cookieとセッション情報
- 復旧コード
- 会社や個人を特定する機密値

## 設定値の分類

| Classification | Examples | Storage |
| --- | --- | --- |
| Public | alias、テーマ、ツール設定 | Git |
| Machine-local | profile、導入フラグ | ローカルのchezmoi config |
| Personal | 氏名、メールアドレス | 原則ローカルconfig。公開可否を個別判断 |
| Secret | token、password、private key | パスワードマネージャーまたは暗号化 |

## 秘密情報の取得

パスワードマネージャーはまだ選定していません。秘密情報が必要になるまでは、対応コードやダミー値を追加しません。

選定時は次を評価します。

- macOS、Linux、Windowsで利用できること
- CLIが利用できること
- 対話なしの失敗が安全であること
- キャッシュやログに値を残さないこと
- CIで本物の秘密情報を必要としないこと

## レビュー時の確認

- 差分に秘密情報らしい値が含まれていないか
- テンプレートの生成結果が値をログへ出さないか
- スクリプトが環境変数全体や設定データ全体を表示しないか
- 外部ファイルのURL、バージョン、チェックサムが妥当か
- Git履歴へ入った秘密情報は、単純な削除コミットでは無効化できないことを理解しているか

秘密情報を誤ってコミットした場合は、最初にその認証情報を失効・ローテーションし、その後に履歴の除去方法を検討します。
